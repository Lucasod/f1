## 3. Findings Log

### Root Cause
The scanner's Passwords/Password assignment pattern on scan-secrets.sh line 36 was:
```
(password|passwd|pwd)[[:space:]]*[:=][[:space:]]*["'"][^"'[:space:]]{4,}
```
It matched the bare identifier `password`/`passwd`/`pwd` anywhere, including inside enum member names such as `EMPTY_PASSWORD`, causing a false positive on `credential.domain.ts`.

### Fix Applied
- `.kilo/scripts/scan-secrets.sh` line 36 changed to:
  ```
  (^|[^[:alnum:]_])(password|passwd|pwd)[[:space:]]*[:=][[:space:]]*["'"][^"'[:space:]]{4,}
  ```
- Added a `(^|[^[:alnum:]_])` lookbehind so the token must be preceded by a non-alphanumeric boundary (or start of line), excluding it from within identifiers.

## 6. Conclusion

**Status: COMPLETED** — security finding resolved with independent review approval.

**Previous Finding:** The Code Reviewer originally issued a FAIL verdict because the scanner correction that fixed the `EMPTY_PASSWORD` false positive also introduced false negatives for compound identifiers (`currentPassword`, `databasePassword`, `ADMIN_PASSWORD`, `user_password`).

**Root Cause:** The first correction introduced the lookbehind pattern `(^|[^[:alnum:]_])` before `(password|passwd|pwd)` to prevent enum members from being flagged. However, this boundary also excluded camelCase and snake_case credential identifiers where the preceding character is alphanumeric (`t` in `currentPassword`, `e` in `databasePassword`) or an underscore (`_` in `ADMIN_PASSWORD`, `user_password`).

**Corrective Implementation:**
- Changed the lookbehind from `(^|[^[:alnum:]_])` to `(^|[^[:alnum:]])` — removes the underscore exclusion so `_` before `password` now matches (detecting `ADMIN_PASSWORD`, `user_password`), while `Y` (alnum) still blocks `EMPTY_PASSWORD` false positive
- Added `export enum` context check in `scan_text_content()` — after grep finds a match, checks if matched lines contain `export enum` and skips the finding if so, preserving the original false-positive protection for enum members
- Added `[a-z](password|passwd|pwd)` camelCase pattern as a second scanner pattern — detects `currentPassword`, `databasePassword`, `adminPassword` via lowercase letter prefix immediately before `password`
- Updated test at line 155 from `check_no_detect` to `check_detect` for `currentPassword = "secretValue"`, and changed label to `"Passwords"`
