## Limitations and Blockers

### BLOCKED: Stripe Connect transfers
The `rk_test_` key is a claimable sandbox key (`rkcs_test_...`). `stripe accounts list` and `stripe transfers list` both return `invalid_request_error` with message "claimable sandbox key with limited permissions." Connect account creation and transfer operations cannot be exercised through the real Stripe API. **Human action required:** Claim the sandbox key via the Stripe dashboard claim URL or obtain a full `sk_test_` key with Connect permissions.

### LIMITATION: Real payment completion on Stripe hosted page
The golden-path test verifies real Stripe Checkout Session creation and webhook delivery, but does not complete card entry + submit on `checkout.stripe.com`. Payment confirmation is done via `triggerStripeWebhook` with the real Stripe CLI signing secret. This tests the backend webhook handling but not the complete frontend-to-Stripe payment flow.

### LIMITATION: Order final status undefined (vendor journey)
The vendor-journey test sets order status to `PAID` directly via API (not through real Stripe payment), and the final status logs as `undefined`. This is FIND-03 from the adendum — order `status` field IS in the API response but may not be populated in all code paths.

### LIMITATION: Financial indicators zero (vendor journey)
Vendor financial dashboard shows `grossSales=0, netExpected=0` because no real Stripe payment was completed through the vendor journey flow. Real payment + webhook → financial movements needed to populate these values.
