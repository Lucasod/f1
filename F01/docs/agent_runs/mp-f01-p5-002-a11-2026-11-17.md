## Root Cause Analysis

**Primary Issue: react-is version mismatch**

Recharts@3.10.1 declares peerDependencies on `react-is: ^16.8.0 || ^17.0.0 || ^18.0.0 || ^19.0.0`. However, npm's dependency resolution installed `react-is@17.0.2` as a transitive dependency (deduped from `@testing-library/dom` → `pretty-format@27.5.1`).

**Why this matters:**
- The project uses React 18.3.1 (with concurrent features: automatic batching, transitions, Suspense)
- `react-is@17.0.2` is designed for React 17 and does not fully support React 18's concurrent rendering internals
- Recharts internally uses `react-is` for element type checking (`isElement`, `isValidElementType`, etc.)
- Version mismatch can cause subtle rendering issues, incorrect element type detection, or failures in concurrent mode

**Evidence:**
- Recharts README explicitly recommends: `npm install recharts react-is`
- React 18 requires `react-is@18` for correct `isValidElementType` behavior with concurrent features
- The `@testing-library/dom` dependency pins `pretty-format@27.5.1` which brings `react-is@17.0.2`, causing npm to dedupe to the older version

**File:** `F01/front/tests/e2e/auth.spec.ts`

```typescript
// Before (flaky):
await expect(page).toHaveURL(/\/login/);

// After (robust):
await page.waitForURL(/\/login/, { timeout: 10000 });
await expect(page).toHaveURL(/\/login/);
```

**Rationale:** The original assertion failed intermittently because Playwright's `expect(page).toHaveURL()` doesn't wait for navigation by default. Using `page.waitForURL()` with a 10s timeout ensures the redirect completes before assertion.
